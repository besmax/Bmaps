# Current location and navigator preparation

## Ownership and contracts

`core:location` owns `LocationService.observe(LocationRequest)`, platform Metro bindings, native permission launchers, and a shared location widget ViewModel. It has no renderer, domain, or feature dependency. `LocationFix` contains WGS 84 latitude/longitude, horizontal accuracy in meters, acquisition time in epoch milliseconds, and optional speed in meters/second and course in degrees clockwise from true north. Course describes movement, not device compass heading.

`LocationService` is the raw platform subscription contract. `SharedLocationService` is the application-scoped distributor used by both `LocationViewModel` and the T2 phone recorder. It owns one native collection while consumers exist, merges the smallest interval/distance hints and activates background policy only when a recorder requests it. Identical effective requests do not restart the stream; explicit Retry/permission refresh restarts the shared native source even when recording retains a consumer; policy changes restart with explicit waiting/quality handling. The last consumer releases listeners/delegates. Distribution preserves each update with bounded queues rather than conflating native batches; overflow explicitly interrupts the recorder. iOS forwards every supplied native location in a batch. Native collection runs on the main dispatcher for iOS manager/run-loop ownership. `LocationRequest` has interval/distance hints and a background flag; background ownership and foreground-start permission policy belong to `domain:activity`, not the renderer. Ordinary map consumers request foreground updates only.

Fixes additionally carry native monotonic acquisition milliseconds, selected provider identity, optional native altitude/vertical accuracy and speed accuracy. Android retains elapsed realtime from the native measurement; iOS maps timestamp age to uptime. Freshness, source ordering, lag penalties and presentation replacement use native uptime when available, with epoch fallback for older/test values. Epoch timestamps remain original history/display anchors. Core Location's altitude reference is not assumed identical to DEM heights. Sensor intervals remain hints, not delivery guarantees.

Platform binding files explicitly import Metro annotations to keep contribution scope resolution tied to `bes.max.bmaps.core.di.AppScope`; wildcard Metro imports produced a contribution hint for Metro’s own `AppScope` in the observed Android compilation.

Android subscribes continuously to `LocationManager.GPS_PROVIDER` and available platform fused/network providers, supplemented by Google Fused Location Provider when Google Play services are available. It requests a current fix and reads fresh cached fixes from enabled providers when attaching. The GPS subscription remains active when connectivity is absent; additional providers improve initial acquisition when satellite reception is poor. Each source retains its latest valid measurement, and `LocationFixSelector` chooses among sources without a fixed GPS/Google/network ranking. Candidates are ranked by reported horizontal accuracy plus a gradual lag penalty relative to the newest acquisition. The first three seconds incur no penalty; additional lag adds two meters per second, or the greatest available reported movement speed if higher. This is an application ranking heuristic, not a corrected sensor accuracy or a predicted position. Equal scores prefer newer acquisition time, then a stable source-name tie breaker. Latest measurements are retained per source, and the previously selected fresh measurement remains a candidate while its source remains available, including when that same source starts returning much coarser fixes. This prevents a 5 m position being replaced by a 500 m position solely because three seconds passed. Moderately less accurate updates can still take over as the lag penalty grows, and every retained measurement expires at its original 30-second freshness limit. Source-local out-of-order updates and equal-time accuracy regressions are rejected. Ordinary selection may move backwards in acquisition time by at most three seconds only to improve accuracy; conflict recovery may instead select an older but still fresh trusted candidate without rewriting its timestamp. All candidate measurements still require validity and the shared 30-second freshness check. Android measures fix age with `elapsedRealtimeNanos`, retains its native uptime and maps age into the shared epoch timestamp so a device wall-clock offset does not incorrectly discard a newly acquired position. Both coarse and fine permissions are declared/requested together; the GPS stream needs precise permission. Approximate-only access is reported with an actionable message. A device with no supported location provider is reported as unavailable. iOS uses Core Location with best desired accuracy and When In Use authorization; the OS chooses available positioning sources. Reduced accuracy is accepted with the reported accuracy circle. The builder centers on the first fresh, valid position and displays its reported accuracy; there is no arbitrary accuracy threshold that can leave an otherwise located map showing the world.

Android source-conflict protection compares the latest fresh `network` measurement with each latest GPS/platform-fused/Google-fused measurement. Network is eligible for this check only with reported accuracy no worse than 250 m. A geodesic separation must exceed both 5 km and five times the sum of reported accuracy radii plus a 100 m/s allowance for the difference in acquisition times. These conservative thresholds are application heuristics for severe disagreement; they neither authenticate network coordinates nor prove GNSS spoofing. Conflicting satellite/fused sources are quarantined for the subscription and excluded from both ranking and the movement-speed penalty. Google and platform fused agreement with GPS is not counted as independent evidence. Available nonconflicting candidates are selected normally; in the reported 53 km discrepancy this selects network. Each source returns to ordinary selection after a fresh eligible network fix agrees with its latest fix. If network expires or is disabled before agreement, quarantined sources stay excluded and the position becomes stale when no fresh trusted candidate remains. Restarting the foreground subscription resets the quarantine. Map coverage never participates in this decision.

`LocationState.sourceConflict` carries an active conflict through the service/presentation boundary. Presentation still independently checks coordinates, accuracy and the 30-second freshness window; it allows an older selected fix during explicit conflict recovery so a real network position can replace a newer disputed GPS position. The selector still rejects source-local out-of-order deliveries. Android logs quarantine changes and waiting-for-trusted-position transitions under `BmapsLocation`, without emitting coordinates or per-fix messages.

A subscription-local one-second coroutine reselects retained measurements so an expired winner can yield to a stored fallback without another sensor callback. Expired measurements are pruned; native provider disablement removes that source and reselects immediately. Disabled native providers and globally disabled location do not accept late fixes. No candidate timestamps or accuracy values are rewritten to make a position look live, and positions are not averaged. The selector, native listeners, Google callback and refresh coroutine are released with the final shared consumer or an effective-policy restart. The three-second lag grace period and movement penalty are application policies, not platform accuracy guarantees; movement, provider cadence, and battery behavior remain device acceptance work.

The Android-only `GoogleFusedLocationSubscription` checks Play services availability without prompting installation, upgrades, or settings resolution. A successful check starts high-accuracy continuous updates with the shared interval/distance hints, allows initial lower-accuracy delivery, and requests cached/current fixes. Native providers are registered first and stay active alongside Google; there is no timeout or Google response required to use their coordinates. Missing, disabled, outdated, or failing Play services, null current fixes, and stale/invalid Google fixes do not interrupt native subscriptions or clear an accepted position. Google deliveries are identified as `google-fused` independently of their embedded provider string and pass through the same freshness, ordering, coordinate, and age/accuracy selection rules. Native callbacks and startup requests are identified by the provider to which Bmaps subscribed, using separate listeners for GPS, platform fused, and network sources. Google task listeners and continuous callbacks deliver on the main thread. Cancellation cancels the current-fix request, removes the continuous callback, and ignores late results; a registration that completes after cancellation triggers removal again. Errors and subscription lifecycle are logged under `BmapsLocation`, without coordinates. SDK versioning is managed by the central catalog; the SDK does not add a requirement for Play services on the device.

Native API references: [Android LocationManager](https://developer.android.com/reference/android/location/LocationManager), [Android permissions](https://developer.android.com/develop/sensors-and-location/location/permissions), and [Apple Core Location](https://developer.apple.com/documentation/corelocation/getting-the-current-location-of-a-device).

Google API references: [FusedLocationProviderClient](https://developers.google.com/android/reference/com/google/android/gms/location/FusedLocationProviderClient), [LocationRequest.Builder](https://developers.google.com/android/reference/com/google/android/gms/location/LocationRequest.Builder), and [SDK setup](https://developers.google.com/android/guides/setup).

## Presentation and lifecycle

The widget ViewModel exposes one immutable `LocationState` and Channel-backed Center/Message events. Presentation validates coordinate ranges, accuracy, freshness, and ordering. Only fixes no older than 30 seconds and no more than 5 seconds in the future are accepted. Presentation independently checks replacement ordering: an older-than-current measurement is accepted only within three seconds and only with strictly better accuracy, except for an explicit source-conflict recovery that still requires validity and freshness. An expired current position does not prevent a fresh replacement. A once-per-second freshness check removes expired dots rather than leaving them displayed as live positions. T2 uses native uptime for phone freshness/order when available, so an epoch clock rollback does not reverse a native fix sequence. Epoch-only fallback and iOS timestamp-age mapping remain sensitive to unusual clock changes.

`LocationTracking` requests foreground permission when entering a map and collects only while the map navigation entry is resumed. Leaving the map, opening another screen or backgrounding cancels its consumer and clears map live state. An active T2 recorder independently retains the shared background consumer; without a recorder, the last map consumer releases native subscriptions. The permission bridge refreshes the subscription after authorization changes; returning from Settings starts a new subscription. Tapping My location after denial opens app settings, and disabled location services open the native location settings. Pending recenter requests wait for a fresh fix and are cancelled by map gestures or leaving the foreground. Sensor failure, denied permission, disabled services, stale position, invalid fixes, and waiting states never block map use. The constructor shows a persistent status notice while a position is unavailable, with progress and Retry/Settings actions. The offline viewer instead shows a red crossed-out My location icon for non-active location states, with a localized accessibility description; it displays no location-status banner or automatic location-status snackbar. Tapping the button opens native location settings when services are disabled, opens app permission settings for denied/precise-only permission failures, and otherwise requests a fresh recenter fix. The icon returns to normal when tracking becomes active. After 30 seconds without a valid initial fix, a timeout notice is shown while native subscriptions continue so a later fix can still recover. The offline viewer has no persistent outside-coverage notice; an explicit recenter outside package coverage retains the existing actionable map message and preserves the viewport. Android diagnostics use the `BmapsLocation` Logcat tag for subscription lifecycle, provider availability/registration, source-conflict transitions, location-status changes, explicit recenter actions, and exceptions. Temporary raw/selected-coordinate, viewer-coverage, per-fix acceptance/rejection, age and accuracy logs have been removed after device investigation. No coordinates are logged and no coordinate-tracing API remains. Camera rejections report a separate localized message. Fixture maps do not activate location.

Features own camera behavior:

- The builder centers once on a fresh fix at zoom 13, clamped to provider/source and renderer limits. A gesture, zoom button, area selection, or explicit My location action ends initial auto-focus. Fresh location updates afterward only move the dot. An explicit recenter keeps the current zoom after the initial view has been established or the user has interacted. A first My location request made while initial acquisition is pending also uses zoom 13; it does not cancel initial focus and then preserve the world zoom. Recentering can replace a regional online pyramid when necessary.
- The offline viewer keeps its existing package viewport. My location preserves zoom and checks the geographic package bounds. Dateline-split packages switch to the covered region before moving the camera. Positions outside coverage show a message and preserve the viewport. Location is a transient overlay, never a saved annotation or a package metadata change.

`core:map-engine` owns geographic marker/accuracy overlay construction, including geodesic circle sampling, dateline unwrapping, tile-rectangle clipping, and a noninteractive accuracy path. It does not know about permission, sensor, or tracking state. Location updates use the existing overlay registry, so tile-source sessions are retained.

## Activity-owned recording and future navigation

[22_TRACK_MODE_AND_TELEMETRY.md](22_TRACK_MODE_AND_TELEMETRY.md) owns the track feature's target behavior, phase status and evidence. T2 source implements `PhoneActivitySession`, shared location distribution, bounded positional/phone telemetry recording, pause/resume/finish, statistics and recovery. Native recording starts only after an explicit foreground action with appropriate precise permission and service availability. No map preparation/start controls are added until T4; T3 adds route matching/progress/alerts and recorded return in the domain owner.

Android retains a location foreground service/notification while recording, and a paused notification while the recorder sensor consumer is absent. It does not auto-restart after process death. iOS recording uses location background mode, visible background updates and disabled automatic location pausing; it requires foreground start/resume, When In Use/Always authorization and full accuracy. Pausing releases background location; ordinary map requests keep the foreground lifecycle described above. Process recovery marks the committed activity interrupted and requires explicit resume; finalization can retry without sensors. GPS loss alone is a quality gap, while authorization/native-owner loss interrupts recording. Write failure stops sensors and exposes the last durable record plus runtime failure. Physical background behavior remains unverified.

The recorder accepts stricter positional quality than the map (five-second age and 50 m accuracy), rejects source conflicts/duplicate or backward acquisitions, and creates segments after pauses/source loss/gaps. Qualified fixes also retain valid native speed/course/altitude with provenance; absent fields remain absent. It does not fabricate speed by differentiating positions or add motion across gaps. Heart rate and Apple Watch remain T7. T3 navigation additionally applies a stricter profile accuracy cap, chronological continuity and bounded route-section search, with explicit uncertainty and gap acknowledgment. It never substitutes an untrusted map dot for a navigation fix. Navigator camera follow and map controls belong to T4.

## User verification

Builds, automated tests, and native device testing are left to the user. No app builds or tests were run for this increment.

Suggested acceptance scenarios on Android and iOS:

- Grant precise/When In Use permission, verify builder focus at roughly source level 13, and verify live dot/accuracy updates on both map types.
- Pan, zoom, or begin area selection before the first fix; verify a later fix does not reset the viewport. Reenter/resume an existing builder entry and verify its view is retained.
- Disable internet and verify the location dot on a downloaded map using a physical GPS-capable device. A fresh satellite fix may take longer without network assistance.
- Deny or revoke access, grant Android approximate-only permission, disable services, and test recovery through Settings. Confirm maps remain usable throughout.
- Test movement, a stale fix, a device without a supported provider, repeated background/foreground changes, and navigation away from the map. Confirm native subscriptions stop and resume correctly.
- Check offline positions inside/outside actual coverage, both regions of a dateline-crossing package, accuracy circles near package edges, and coexistence with annotation editing.
- Verify provider limits and different tile sizes/layouts constrain initial zoom appropriately. Inspect battery use and map responsiveness on physical devices before treating native acceptance as complete.

That correction shared freshness/coordinate validation with presentation and retained the GPS fix against worse fallback accuracy until it expired.
