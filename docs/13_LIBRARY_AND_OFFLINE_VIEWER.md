# Library and offline viewer

Phase 6 implementation, 2026-09-14. Source review only; builds, schema generation, automated test execution, and manual/native acceptance remain with the user.

## Navigation and library

Library orientation layout: when the available content window is wider than it is tall and at least 600 dp wide, `LibraryLayout` uses a 200 dp independently scrolling left panel for search, vertical filters and transfer progress/cancellation. The remaining width belongs to an adaptive map-card grid with a 240 dp minimum cell width and 16 dp gaps; download cards, loading/error/empty states and pagination span the full grid width. Portrait and narrower windows keep a single column with controls at the top and the existing 720 dp width cap. Both layouts use the same remembered grid state and stable map/download keys. The tree action FAB remains bottom-right, with trailing scroll space to reach cards underneath it. Layout selection is based on current Compose constraints, including resized windows, and adds no platform orientation dependency. Small layout/filter composables stay in `LibraryScreen.kt`. Static source checks only; builds, tests and device/emulator layout acceptance remain with the user.

Library stability: package summaries, build progress and verification progress are mapped in `catalog.presentation` into `@Immutable` display models before entering observed state. `LibraryState` uses immutable lists and a persistent set of string IDs; zoom levels are copied into a sorted immutable list, and bounds are copied into primitive display values. The card header receives only name/avatar, while metadata, status, recovery and actions receive narrow stable parameters. Status changes still update the card container and relevant controls, but leave unchanged header/metadata inputs equal; action callbacks capture string IDs. Pagination, filtering, item keys, verification dialog retention and repository commands preserve their existing behavior. Source/static checks only; builds, tests and device recomposition acceptance remain with the user.

Library UI decomposition (2026-10-11): `catalog.ui.LibraryScreen` retains ViewModel resolution, state observation, lifecycle collectors, native document access and callback wiring. `LibraryList` owns the lazy grid and preserves map/download item keys; portrait uses one column. `LibraryControls` separates search, filters and transfer progress; `LibraryDownloadItem` and `LibraryMapItem` render their respective cards, with map header, recovery and action sections split locally. `LibraryDeleteDialog` renders deletion confirmation. These small screen-local composables remain together in `LibraryScreen.kt`; the substantial animated FAB is isolated in `LibraryActionFab.kt`; `LibraryPresentation.kt` separately contains shared display labels and formatting used by both the screen and package details. Extracted components receive data and callbacks; repository and ViewModel ownership are unchanged. Static source checks only; builds, automated tests and device/emulator acceptance remain with the user.

The home destination is the local map library. A circular plus FAB opens a floating menu with **Build a map**, **Import map file**, and **Activities** actions; choosing Build opens the constructor and choosing Import opens the native document picker; tapping a ready map opens `viewer/{packageId}`. Incomplete entries open their details and retain the existing missing-tile restore controls. There is no bottom navigation or retained tab back stack. Constructor and viewer navigation return to the library through Back. The top-bar gear opens the existing preferences dialog, retaining its dialog-owned draft and ViewModel lifetime.

Search, readiness filters, favourites, and filter-bound keyset pagination execute through `core:database`. Card/detail size uses the sum of file lengths in the actual ready or staging package directory, reconciled when summaries are read; it includes all raster layers, generated elevation layers, DEM, annotations and configuration. Device-local generation jobs/caches outside that directory are excluded. Changing search or filters resets the loaded page count. Ongoing downloads remain above the result list even when filters exclude their package. Details show WGS 84 bounds, exact downloaded zoom levels, tile counts, size, status, and elevation availability. Empty search results are distinct from an empty library.

Favourite writes use `LibraryState.savingFavourites` to prevent duplicate presses and disable only the star button. They do not enter the general per-package `busy` set, so the card stays enabled and retains its normal Material colors during the write. Removing a favourite under the Favourites filter still removes the entry through the repository query. Source/static checks only; builds, tests and device appearance acceptance remain with the user.

Each package supports a favourite flag and six built-in vector avatars: map, mountain, forest, water, city, and camp. Both library details and viewer details can change the avatar; favourites can be toggled in either screen. These are device-local library preferences, stored separately from download and manifest metadata. They survive checkpoints, finalization, reconciliation, and ordinary app restarts. Photo picking and avatar export are not implemented.

The library action menu is owned by `LibraryState.actionsExpanded`. A focusable popup dismisses on outside presses (including the top bar), Back, the root FAB, or an action selection. Import is disabled while a transfer is busy; transfer progress/cancellation stays in the list. The tree animation grows three curved branches upward from the circular FAB root over 480 ms, then blooms three labeled capsules at their tips. Icons and labels fade in after 340 ms over the remaining 140 ms. The same Material FAB root remains composed throughout the transition, rotating its plus into a close icon. The popup carries a transparent close hit target over the root and draws branches only above its bounds. It never draws a duplicate root circle/icon, so collapse removes only the popup rather than switching from a painted root to a newly created FAB. Closing retracts the branches over 280 ms and fades action content out in the first 100 ms. Motion is eased without bounce; paths and transition values remain composition-owned. Existing Android navigation/renderer checks open the plus menu before Build; they were not run. Builds and device/emulator appearance, popup interaction and motion acceptance remain with the user.

## Persistence and deletion

Room schema version 2 adds `package_preferences`, keyed by package ID with a cascading foreign key. The explicit 1-to-2 migration creates this table without changing existing package/job records. The version 1 exported schema is retained. Generate and review version 2 during the user's next build; no schema hash has been fabricated.

Favourite filtering is part of the SQL query and cursor identity. Repository observations also react to preference updates, including changes in an already open viewer. Unknown avatar keys display the default map icon.

Deletion requires an explicit confirmation naming the map. Existing jobs go through the download executor so native scheduling and runner work stop before package deletion. Confirmed deletion also permits a job that completed while the confirmation was open. Packages without jobs use the repository directly. The repository marks DELETING, closes owned MBTiles sessions, removes staging/final files, and deletes metadata and cascading preferences. Existing reconciliation retries interrupted deletion; errors remain actionable in the library.

## Offline rendering and lifetime

`ViewerViewModel` injects only `PackageRepository`. It opens a verified `OpenedPackage` and supplies its local MBTiles tile sources to `RasterMapRenderer`; no online source, provider credentials, HTTP cache, or download executor participates in viewer tile reads. Existing queued downloads remain independently managed by Phase 5 and must be stopped when measuring viewer-only network activity.

The renderer runs inside the package-owning coroutine. Retry cancels and joins that coroutine before opening its replacement. Renderer cancellation joins tile reads and closes tile sources before the enclosing package session closes. The navigation entry owns the ViewModel, preserving the renderer and viewport across ordinary recreation and background/foreground transitions. Leaving the entry releases the session. Viewport persistence across process death or reopening a popped viewer is not promised.

The initial viewport centers the downloaded geographic area within its tile-aligned region. Continuous downloaded levels use an automatic tile pyramid when its dimensions fit the engine. Every downloaded level is also available explicitly. Separated levels, or an automatic pyramid that would overflow engine dimensions, use explicit level selection without silently dropping levels. Explicit-level mode limits zoom-out to roughly eight tiles along the larger extent, avoiding unbounded requests when a large high-detail region has no lower-resolution tiles. Display zoom and source level remain separate controls. A selected regional level can exceed zoom 18; coordinate precision is bounded by the existing level-52 geometry limit and renderer dimensions.

Date-line-crossing maps expose both geographic halves as separate regions with canonical XYZ addressing. They do not stretch a narrow crossing selection across the whole world. Switching levels preserves the geographic center when possible; switching halves fits the new region. Missing and unreadable local tiles have visible messages, and package-open/configuration errors support Retry. Map details retain downloaded bounds, levels, size, elevation availability, and elevation metadata. Phase 7 renders all aligned visible raster layers and persists their order, visibility, and independent opacity. The Layers dialog also exposes downloaded zoom levels and date-line regions; see `14_RASTER_LAYER_COMPOSITION.md`.

## Phase 9 center readout

The offline viewer overlays a fixed black cross with a white outline at the actual map viewport center. A bottom surface shows latitude/longitude in the saved format and optional elevation rounded to one decimal meter in the compact form `H: 27.3 m`. Transformation accuracy, coordinate epoch and dataset vertical reference are omitted from the readout; the underlying metadata is retained. The readout wraps its content and is centered at the bottom. Portrait uses three left-aligned rows: `Lat: …`, `Lon: …`, and `H: 15.0 m`. Coordinate formats and the saved CRS remain respected; EPSG:3857 uses separate `X`/`Y` rows in meters. Landscape joins the existing coordinate and elevation labels into one line, with ellipsis if constrained. Annotation controls sit above it. Landscape layers, zoom, location and attribution share a single right-side column with 8 dp gaps; the column scrolls when height is insufficient. Portrait separates this rail into three groups: layers at the safe top opposite Back, two zoom buttons at the safe-area center, and location/attribution at the safe bottom. Buttons within groups keep 8 dp gaps; free space separates the groups. Bottom content reserves symmetric 80 dp margins in both orientations so the centered readout does not enter the control rail. The independent `MapPositionViewModel` observes camera snapshots and preferences and owns a package session for DEM access; it closes the session when cleared. While coordinates are being calculated, both orientations show only one `...` row and hide elevation. Missing DEM displays `H: —` in portrait and omits altitude in landscape; unavailable samples, coverage and unsupported data have explicit labels. See `17_ELEVATION_READER.md` for the supported subset and pending user acceptance.

## Offline immersive mode

A parallel vertical swipe with two fingers starting on the map toggles immersive mode in either direction. Repeat the gesture to restore the interface. Single-finger panning and two-finger pinch zoom remain available; changes in finger separation or rotation reject the immersive gesture. Recognition requires both fingers to travel at least 48 dp (or three touch slops, whichever is larger), then consumes the remaining gesture to prevent accidental map actions. The map also exposes a Show/Hide map controls accessibility action.

`ViewerState.immersive` owns this session state and resets when another package opens. Immersive mode hides application controls, the crosshair/readout, editing panels and vertex handles, object callouts, dialogs, notices and snackbars. Raster layers, annotation geometry and the current-location marker remain visible. Annotation taps and long presses cannot edit hidden tools. Camera observation, DEM access and foreground location tracking remain mounted; toggling does not reopen the package or recreate the renderer. Native system bars are unchanged.

Source implementation only; builds and device testing remain with the user. Manual acceptance should cover toggling in both directions, pinch zoom and panning, restoration during annotation editing, ongoing GPS updates, accessibility actions, and Android/iOS gesture handling.

## Library size refresh — 2026-10-09

The user reported a card size resembling only the base layer. Source inspection found that the card/detail already displayed `PackageSummary.sizeBytes`, but summary reads trusted the cached Room package size. They now remeasure the complete ready directory (or staging directory for incomplete maps) using bounded filesystem metadata access, without reading tile/DEM payloads. Repository serialization and a fresh record lookup prevent an observation snapshot from overwriting concurrent package changes. Changed totals are persisted with the download job's `packageBytes` in the same checkpoint, preserving modification timestamps and pagination order. Database writes occur only when a byte total differs. Missing/unreadable directories retain the last recorded value and existing package status; no synthetic base-layer fallback is used.

The library refreshes its query each time its destination resumes, including returning from the viewer, while keeping search, filters and loaded page count. Both list observations and package details use the corrected summary path. Size includes every file physically present in the package directory, including still-retained old generated versions; private generation work files remain outside committed map size. Partial transfers are remeasured on an observation/refresh; this change does not add filesystem polling.

Source regression scenarios extend `eachLayerHasItsOwnLimitAndElevationIsExcluded` with multiple layers, DEM and annotations, and `generatedElevationLayerReplacementAndSizeAccounting` with the generated layer. They deliberately replace cached totals with a base-only value after repository initialization and verify list/detail totals, catalog/job repair and stable timestamps. Scenarios are registered for Android device and iOS execution but were not run. Static source/header/XML checks only; builds, runtime tests and card/resume acceptance remain with the user.

## Full verification in map details — 2026-10-11

Ready, corrupt and missing map details provide **Full verification**. A dialog-owned `PackageVerificationViewModel` observes the selected package independently of the filtered list and runs the explicit repository check. It reports waiting, file inventory, checksum, annotation database, tile database integrity and tile coverage stages. Tile coverage publishes aggregate checked/total counts across all layers every 256 tiles and at each layer boundary. The tile-stage bar is determinate; other stages are indeterminate. Results remain in the dialog as success, missing/damaged resources, an operational failure or cancellation. A successfully revalidated damaged package returns to READY. Incomplete downloads must finish or restore before full verification.

Cancel requests coroutine cancellation and shows a stopping state until work releases its resources. Closing the dialog clears its separate ViewModelStore and cancels its observation and verification. Cancellation is propagated rather than stored as corruption and does not clear a dirty verification flag. A cancelled read-only check of an unchanged trusted package keeps its prior verification state; any annotation-manifest repair already started remains marked dirty until verified. File hashing checks cancellation between 64 KiB chunks; tile scanning checks it for every row. Synchronous SQLite statements, including `quick_check`, finish their current native call before cancellation can be observed; the UI remains in the stopping state meanwhile. Connections/statements close through their owned cleanup paths. The existing repository/file locks serialize verification with package mutation and deletion.

The details snapshot stays available even when a failed check removes the map from the active READY filter. The dialog's own package observation refreshes its status, so the user can read the result and retry. Avatar changes are disabled during verification.

Normal startup and package opening now use cached verification as described in document 11. Existing packages receive one deep check after the Room 2-to-3 upgrade. Full verification is local and starts no network work.

Presentation regression tests cover completion/failure, duplicate-start prevention, cancellation/retry and dialog disposal. Native storage scenarios cover trusted restart, manual corruption detection/recovery and cancellation. These tests are authored but unexecuted. Only source, resource, migration SQL and license checks were performed; builds, Room schema generation, Android/iOS device acceptance and performance measurements remain with the user.

The coordinate trace and viewer-only diagnostic effect/recenter log are removed. Geographic coverage, marker filtering and recenter behavior remain unchanged.
